适用于 2026-10-28 更新后的源码版。按钮名称按当前界面编写；游戏中的位置、库存、任务奖励和交易结果均以服务器确认为准。

## 1. 第一次使用

1. 按[项目首页](../README.md)安装依赖并运行 `desktop.py`。
2. 在“账号管理”点击“导入钱包”，每行输入一个钱包私钥，设置或输入统一主密码，点击“加密导入”。
3. 勾选账号，点击“批量上线所选”。这一步建立连接，不会替你启动刷怪任务。
4. 等待账号显示在线。如果显示“待创建角色”，点击该行“创建角色”，填写名称并选择战士、守卫或弓手。
5. 选择需要执行任务的在线账号，设置方案和过滤条件，再点击“启动所选账号”。
6. 要单独观察某个账号，点击该行“切换显示（不断线）”；其他账号保持在线。

程序不会在启动时自动登录，也不会因为导入钱包就自动购买商品。

## 3. 钱包与账号状态

### 导入和解锁

- 多个钱包使用同一个主密码加密。主密码至少 6 位，应用退出后不会继续保留在内存中。
- 私钥用于本机签名；创建角色、连接游戏或执行商城操作使用相应账号的会话。
- 已保存的钱包通常只需在本次运行中解锁一次。主密码错误或保险库文件损坏时，该账号无法完成签名登录。
- 忘记主密码或丢失任一加密分片后，需要重新导入原私钥，程序没有主密码找回功能。

### 状态与处理

| 显示状态 | 含义 | 下一步 |
| --- | --- | --- |
| 离线 | 尚未连接，或连接已经关闭 | 单独连接或勾选后批量上线 |
| 连接中/签名登录中/读取角色资料 | 正在完成登录步骤 | 等待结果，查看状态与日志 |
| 待创建角色 | 登录已识别到该钱包没有游戏角色 | 点击该账号的“创建角色” |
| 在线 | WebSocket 已连接 | 等待游戏世界和角色快照就绪后执行任务 |
| 登录失败 | 签名、资格、网络或资料读取失败 | 根据该账号日志处理后重试 |

“已连接”不代表所有角色资料和怪物数据已经到达；如果操作暂不可用，先等待世界数据完成加载。

### 批量上线

“批量上线所选”最多同时进行 3 个账号的完整登录流程，其他账号排队。这个数字是登录并发数，不是最多在线账号数。

未创建角色的账号会释放上线名额，单独统计为“待创建角色”，不会在后台弹出创建窗口，也不会因此阻止其他账号继续上线。程序不会批量猜测角色名或默认替你选择职业。

单个登录等待超时会退出该次尝试并继续处理其他账号。旧批次的超时回调不会用来断开后来重新发起的登录。

### 创建角色

1. 在账号列表点击“创建角色”。
2. 输入 2–12 个字母、数字或下划线组成的名称；中文属于可接受字符。
3. 选择战士、守卫或弓手并确认。
4. 等待服务器创建成功后继续进入游戏；失败时按提示修改名称或重新尝试。

取消创建不会影响其他在线账号。稍后可以再次点击该账号的“创建角色”。

## 4. 多账号任务方案

### 按钮区别

| 按钮 | 实际行为 |
| --- | --- |
| 批量上线所选 | 登录勾选账号；不自动开始战斗 |
| 启动所选账号 | 将当前方案应用到勾选的在线账号，并开启自动战斗；离线账号跳过 |
| 暂停方案 | 关闭所选账号的自动攻击、自动接任务和任务自动进图，并停止当前自动移动 |
| 停止方案 | 当前版本与“暂停方案”执行相同的停止逻辑，游戏连接仍保持 |
| 批量下线所选 | 停止相应游戏自动任务并断开连接，同时取消这些账号尚未开始的排队登录 |

“暂停方案”没有保存执行游标的一键续跑功能。需要继续时，核对勾选账号和方案，再点击“启动所选账号”。

### 三种方案

| 方案 | 自动接打怪任务 | 按任务地图进图 | 攻击目标 |
| --- | --- | --- | --- |
| 自动任务：接任务并按任务地图战斗 | 开启 | 开启 | 当前地图中通过过滤的怪物 |
| 自由刷怪：留在各账号当前地图 | 关闭 | 关闭 | 当前地图中通过过滤的怪物 |
| 精英狩猎：只攻击精英怪 | 关闭 | 关闭 | 服务器标记为 `ELITE` 的怪物 |

自由刷怪和精英狩猎不会因为你在下拉框选择了其他地图，就立即将所有账号传送过去。需要先使用地图操作进图；“任务做完后继续刷图”的目标另有触发条件。

### 方案参数

| 参数 | 行为 |
| --- | --- |
| 允许自动用药 | 应用到所选账号的生命药水开关；会消耗库存生命药水 |
| 等级范围 | 只考虑范围内的怪物；范围包含上下限，无法识别等级的怪物会被跳过 |
| 避开附近有玩家的怪 | 跳过怪物附近有其他玩家的目标；当前检测半径为 180 游戏单位 |
| 任务做完后继续刷图 | 自动任务没有下一项可接、或遇到任务接取额度限制时，按设置转入指定地图刷怪 |
| 后续刷怪地图 | 上述任务后续逻辑的目的地；不包含需要秘宝通行的地图 7 |

避让检测会把你的其他账号也当作“其他玩家”。多个账号挤在同一个怪物附近时，可能相互避让并继续巡逻。这时应检查该开关是否符合你的组队操作意图。

### 批量方案与“任务有限模式”

**“自动任务”方案不等于“任务有限模式”。** 当前批量启动会关闭各账号的“任务有限模式”，并覆盖自动用药、等级范围、任务接取、任务地图、精英筛选、任务后续刷图和避让开关。

如果希望没有进行中的怪物任务就停止攻击，应在启动方案后，进入各账号控制台勾选“任务有限模式”。再次点击批量“启动所选账号”会重新应用批量参数。

## 5. 自动战斗与目标选择

- “自动追击与攻击”：搜索当前地图中服务器已下发的存活怪物，应用过滤条件后追击或攻击。
- “攻击选中怪物”：从怪物列表选择一行，达到攻击距离并具备攻击票据后发起攻击。
- “只打精英怪”：只接受 `ELITE`，不会把所有 Boss 自动当成精英目标。
- “限制怪物等级”：可单账号设置上下限；目标超出范围后停止对它的追击。
- “自动使用生命药水”：当前脚本在生命不高于最大生命的 50%、有药水且服务器冷却结束时请求使用。

自动用生命药水和体力恢复药水是两项不同功能。批量“允许自动用药”控制生命药水，不会自动使用体力恢复药水。

### 职业差异

战士和守卫使用近战接近逻辑。弓手使用远程逻辑，在约 300 单位内准备攻击，发送命中帧前再次检查目标距离与状态；具体能否命中仍由服务器验证。

默认角色的攻击方向、动画时序和装备攻击速度会参与命中帧调度。旧攻击结束回调不会覆盖随后一次攻击的动画状态。

### 没有怪物或暂时不攻击

当前地图没有合适目标时会进入搜索或巡逻。北部雪地和秘宝之地使用覆盖整图的巡逻线；主城不进行找怪巡逻。

整图搜索通过移动扩大观察范围，不会直接取得服务器尚未下发的所有怪物坐标。地图上没有标记，不等于服务器整张地图绝对没有怪物。

这些提示通常需要先检查对应条件：

| 提示/现象 | 常见原因 |
| --- | --- |
| 等待攻击票据 | 服务端还未允许下一次攻击，不会绕过票据连续发送 |
| 发现怪物却不打 | 等级、精英、任务模式或附近玩家过滤了该目标 |
| 路线暂不可达 | 当前坐标或碰撞数据无法构造路径，稍后换目标/重试 |
| 目标暂时跳过 | 服务端拒绝该目标，或攻击前目标已死亡、移动或超出范围 |
| 手动移动期间不打怪 | 手动移动或切图优先，自动攻击暂时让路 |

## 6. 地图、移动与复活

### 地图路线

| 地图 | 常规连接 | 额外条件 |
| --- | --- | --- |
| 1 主城 | 2 北部雪地、4 西部荒野、5 废弃遗迹、6 南部森林 | 到达对应入口 |
| 2 北部雪地 | 1 主城、10 冰封洞穴 | 到达返回入口 |
| 3 石谷 | 6 南部森林 | 从南部森林中转 |
| 4 西部荒野 | 1 主城、9 失落绿洲 | 到达返回入口 |
| 5 废弃遗迹 | 1 主城 | 入场规则由服务器校验；需要用券时勾选“使用入场券（遗迹）” |
| 6 南部森林 | 1 主城、3 石谷、8 黑石洞窟 | 到达对应入口 |
| 7 秘宝之地 | 返回主城 | 进入使用秘宝之石或有效通行资格 |
| 8 黑石洞窟 | 6 南部森林 | 后台碰撞寻路 |
| 9 失落绿洲 | 4 西部荒野 | 后台碰撞寻路 |
| 10 冰封洞穴 | 2 北部雪地 | 后台碰撞寻路 |

点击地图会移动到入口或派发对应请求，不是无条件瞬间传送。服务端仍检查当前位置、移动速度、战斗限制与入口条件。

“停止移动”取消当前入口或坐标移动，不等于下线。如果自动任务仍开启，之后可能再次按任务目标安排移动；需要全面停止时使用账号中心的暂停/停止方案。

角色阵亡后，脚本发送复活请求，使用服务器确认的地图和坐标；不假定一定回到城镇。“复活后自动进入”可指定普通地图；它与任务后续刷怪、任务地图切换共同影响复活后的目的地。秘宝之地不加入自动复活回图选项。

### 批量地图

1. 打开“批量地图”或“大地图批量管理”。
2. 选择要观察的地图，勾选窗口里的在线账号。
3. 在地图上点击坐标或怪物标记。
4. 选择需要的操作：

| 操作 | 行为 |
| --- | --- |
| 让所选账号进图 | 给所选账号安排前往当前地图的路线 |
| 移动到所选坐标 | 已在当前地图的账号直接寻路；其他地图的账号先切图再前往目标坐标 |
| 追击所选位置附近精英 | 必须选中精英标记；只对已经在该地图的所选账号发起追击 |
| 刷新地图 | 更新窗口中的地图和账号信息 |

秘宝之地仍要求各账号有有效通行资格；进图操作不会替账号自动消耗新的秘宝之石。大地图坐标与怪物来自已连接账号的观察数据，不是服务器全知地图。

秘宝之地使用专用传送流程，跨图移动不沿用普通地图的“进图后继续前往坐标”链。先在各账号控制台完成秘宝传送并确认到达，再派发该地图内的坐标移动。

## 7. 任务与装备交付

“任务”页显示服务器任务、进度和状态。“刷新角色与任务”重新读取角色、装备与任务数据。

| 开关 | 用途 |
| --- | --- |
| 完成后自动接打怪任务 | 自动寻找并接取下一项可用的怪物任务，不自动接取所有类型任务 |
| 按任务地图自动进图 | 为当前任务寻找地图入口路线 |
| 任务有限模式 | 必须有未完成的怪物任务才允许自动攻击，并按当前任务地图过滤目标 |
| 无可接任务后刷指定地图 | 没有下一项怪物任务或遇到额度限制时，按设置进入后续刷怪流程 |

希望任务结束后停下时，关闭后续刷图，并使用任务有限模式。不要把这一配置与批量启动会重置的开关混淆。

### 交付装备领取奖励

1. 先有一条已经接取、尚未完成的装备交付任务。
2. 在任务表中选中它，点击“交付装备任务 · 手动选择装备”。
3. 程序从服务器获取候选装备；不会自动帮你挑选。
4. 勾选数量达到任务要求后，确认按钮才可用。已穿戴、已标记锁定或上架的装备不进入可选项。
5. 点击“确认消耗所选装备并交付”，等待服务器结果。

确认交付会消耗选中的装备。提交处理中关闭窗口不代表请求被撤回，也不会允许立即开启另一轮重复交付。若结果不确定，应先刷新任务和背包再操作。

只有服务器返回交付成功后，程序才提示成功并刷新奖励、任务和背包。装备兑换钓竿等任务也使用这个流程；完成条件和奖励由具体任务决定。

## 8. 秘宝、体力药水与木钓竿

入口在游戏控制台左侧“秘宝、钓鱼与 Boss 通行”。面板显示当前服务器确认的体力药水、秘宝之石数量和钓竿持有情况。

| 按钮 | 前提 | 消耗或结果 |
| --- | --- | --- |
| 使用 1 瓶体力恢复药水 | 角色存活、体力未满、库存有药水 | 手动消耗 1 瓶，等待服务器确认恢复 |
| 使用 1 颗秘宝之石 | 有石头、未在秘宝之地、当前没有有效通行 | 消耗 1 颗，开启一小时通行并请求进入 |
| 重返秘宝之地 | 有尚未到期的通行资格 | 不额外消耗石头，显示剩余时间 |
| 离开秘宝之地回城 | 当前位于地图 7 | 返回主城，通行倒计时继续 |
| 消耗 1 根木钓竿 · 钓鱼 | 背包里有实际木钓竿，服务器允许使用 | 消耗一根，约 3 秒，等待服务器结果及库存核对 |
| 重返 Boss 地图 | Boss 通行尚未到期 | 不消耗新凭证，显示独立倒计时 |

秘宝通行离线也计时；到期后按服务器位置通知回城。库存和位置不会在刚点击按钮时就被假定为变更成功。

秘宝进出和使用钓竿前会关闭当前自动攻击、自动接任务和任务自动进图，并停止移动。抵达后若要继续打怪，需要手动启动合适的方案。

重复操作会暂时禁用，等待结果；超过等待时间会提示核对库存，不自动重复消耗。战斗中或服务器规定的其他受限状态可能拒绝请求。

钓鱼按请求、开始、结果、库存核对处理。结果包括经验鱼、装备、道具、FishPond NFT 或空竿；以服务器回包为准。钓鱼及核对期间拦截移动、追击、战斗、切图和再次消耗。超时点击“核对钓鱼结果与库存”，确认已经结束后只刷新库存，不重发请求；没有自动连续消耗鱼竿的循环。

FishPond NFT 兑换需选择具体道具并确认，提交后该 ID 在本次会话内不重复提交（含超时）。官网提示成功后道具消失，兑换至绑定钱包，预计 3 个工作日；实际处理以服务器为准。Boss 拍卖只读展示当前页，付款需在官网连接钱包确认。

## 9. 背包、装备与角色资料

- 角色面板展示服务器资料中的职业、等级、生命、经验、疲劳、属性和已穿戴装备。
- “背包”可查看物品、属性及品质；装备可以穿戴，角色与社交页中已穿戴物品可卸下。
- 单选一件同部位装备可与当前穿戴装备比较；按住 Ctrl/⌘ 多选同部位装备，可以比较多件物品。
- 职业限制按装备的 `requiredClass` 处理，不适合当前职业的装备不会被自动挑选穿戴。
- “自动装备更优装备”按脚本的综合属性分数选择升级，不是服务器提供的绝对最优配装结论；会实际发送穿戴请求。希望完全手动配装时关闭该选项。
- 钓竿等道具不应作为普通装备穿戴，其操作转到对应玩法。

“上架出售”目前保留为说明入口，没有接通自动上架接口，不会因为点击它就成功出售装备。

## 10. 状态、社交与推送

“角色与社交”包括背包与装备、状态与附近玩家、世界聊天。聊天发送使用当前账号。战斗模式的切换仍受主城、冷却和服务器规则限制，不代表自动任务会自行执行 PVP。

“推送设置”可填写 Lark 自定义机器人 Webhook，并按类别控制装备掉落、任务完成、疲劳耗尽、购买提交和出售事件通知。首次加载背包作为基线，不会把已有全部装备重新当成新掉落通知。

“疲劳耗尽后断开并退出当前登录”只在收到服务器确认疲劳为 0% 时触发。勾选后会断开该账号，下次需要手动登录；未勾选时仅按已启用的通知设置提示。

商城购买通知表示交易已提交，不等于链上已确认或商品一定已到账。出售通知需要实际收到出售事件；它不意味着本工具已经具备上架出售能力。

## 11. 商城与监控

桌面版商城绑定当前激活账号，多个游戏账号在线不代表同时运行多份商城秒购。切换账号会停止旧商城监控，载入新账号的独立筛选配置；旧账号的游戏连接仍保留。

### 操作顺序

1. 核对当前账号，进入“商城与监控”。
2. 用“立即刷新”查看商品与接口状态。
3. 设置扫描间隔、并发、品质、价格和购买限制。
4. 点击“开始监控”持续扫描。仅监控不会因为出现匹配商品就自动购买。
5. 确认需要自动购买时，再点击“启动秒购”。这一步会允许使用当前账号私钥签名并提交交易。
6. 使用“停止秒购”关闭自动购买；需要停止扫描时再使用“停止监控”。

| 设置 | 含义 |
| --- | --- |
| 扫描间隔 | 两轮持续扫描之间的等待时间，界面最小按 5 秒处理 |
| 并发 | 每轮商品请求的并发量，不是同时签名购买的数量 |
| 品质 | 多选候选商品品质 |
| 价格范围 | 当前匹配规则为 `最低价 ≤ 商品单价 < 最高价` |
| 总预算 | 自动购买的商品金额累计限制，不是链上 gas 费用上限 |
| 最多件数 | 自动购买数量限制，默认单次最多 1 件 |

商品详情中的“获取调用参数（创建报价）”会创建报价并展示调用信息，本身不等于已经完成支付。

监控、自动购买默认保持关闭，需要手动启用。关闭窗口、停止任务或切换账号能停止后续操作，但不能撤回已经提交的网络请求或链上交易。具体成交和扣款结果应查看服务器与交易回执。

## 12. 功能优先关系

| 当前操作或状态 | 对其他自动行为的影响 |
| --- | --- |
| 未上线、世界数据未就绪、阵亡或等待复活 | 不执行正常自动攻击和坐标移动 |
| 正在前往地图入口或切图 | 自动攻击让路，不同时追击新怪物 |
| 手动坐标移动 | 自动攻击暂时让路，先完成手动移动 |
| 秘宝进出、使用木钓竿 | 停止当前自动任务和移动，等服务器确认位置 |
| 批量启动方案 | 覆盖该方案涉及的单账号开关，包括关闭任务有限模式 |
| 暂停/停止方案 | 游戏保持连接；不会同时停止另行启用的商城监控 |
| 批量下线 | 停止所选账号游戏连接；当前激活账号下线时也停止其商城监控 |
| 切换显示其他账号 | 其他账号的游戏连接与任务继续；商城会重新绑定当前账号 |

## 13. 日志、故障与更新

| 现象 | 处理入口 |
| --- | --- |
| 未创建角色时没有进入游戏 | 账号中心点击该账号的“创建角色”，后台不会自动弹窗 |
| 点击启动后没有开始登录 | “启动所选账号”只处理在线账号，先用“批量上线所选” |
| 账号在线但一直不打怪 | 查看控制台是否进图、过滤条件、任务模式、是否正在手动移动及攻击票据提示 |
| 多账号都在搜索空闲区域 | 检查“避开附近有玩家的怪”，账号之间也可能互相避让 |
| 秘宝按钮灰色 | 核对库存、通行剩余时间、当前地图及是否有请求待处理 |
| 交付按钮不能确认 | 核对已接取任务、所选数量、装备是否满足服务器给出的候选条件 |
| 角色位置回退 | 查看运行日志中的服务器移动纠正；不要把客户端预计坐标当作已确认位置 |
| 窗口持续无响应 | 检查自动生成的 UI 卡顿调用栈日志 |
| GitHub 已有新代码但“检查更新”没有提示 | 程序检查的是 Release 安装包，源码提交不等于已发布新的 exe |

Windows 卡顿日志默认位于 `%LOCALAPPDATA%\TabbyDesktop\logs\ui-freeze.log`。主线程连续超过约 2.5 秒没有心跳时记录调用栈，日志过大会轮换。运行日志页最多保留 2500 行，可用“清空日志”清理显示。

源码版更新通过获取最新源码后重新运行；Windows 安装包版通过右上角“检查更新”查找 GitHub Release。本文描述的功能以当前源码为准，旧安装包可能尚未包含。

分享日志前检查其中的账号、请求和运行环境信息；不要把私钥、Token、Webhook、钱包分片或保险库备份提交到仓库。
